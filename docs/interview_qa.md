# 候选人 FAQ 模板（27 届应届毕业生版）

> 面试官问到高频问题时，AI 的参考回答模板
> 校招 / 实习招聘的考察逻辑与社招不同，**潜力 > 经验，基础 > 项目，学习能力 > 业务深度**

---

## 一、个人类

### Q：请用 30 秒介绍一下你自己

**模板 A（简洁版）**：
> 我是 27 届本科应届毕业生，目前在 <某某 AI Agent 初创公司> 实习，专注于 LLM 应用工程。在实习中主要做 RAG 和 Agent 系统，从架构到落地全栈。基础扎实（GPA 3.7+），学习速度快，最近做的 AI-Me 项目用对话展示候选人能力。

**模板 B（故事版）**：
> 我对 LLM 的兴趣是从大二蹭 <某某课程 / 某某项目> 开始的，那时候用 GPT-3 玩了几个 demo。后来加入 <某某实验室 / 自学路线>，做了一些 RAG / Agent 项目。再到现在的实习，把 LLM 真正落地到业务里。所以我的路线是：兴趣 → 自学 → 实习 → 项目。

### Q：你是 27 届的，为什么这么早投？

**思路**：
- 不早，这是正常节奏（2026 暑期实习 + 2026 秋招）
- 提前批 / 内推渠道开放得更早
- 面试官考察的是你的准备程度，不是入职时间

### Q：为什么选择 LLM / Agent 方向？

**4 要素**：
1. **技术前沿**：LLM 是最有活力的方向
2. **工程价值**：能直接落地业务，不是纯研究
3. **个人兴趣**：从大二开始折腾，越玩越有意思
4. **就业市场**：缺口大，校招薪资好

**为什么不做预训练**：
- 对工程落地更感兴趣
- 算法研究门槛高（顶会论文）
- 应用层创新空间也很大

### Q：为什么不读研？

**适合本科同学的回答**（如果决定不读研）：
1. **个人规划**：想早点进入工业界，做实事
2. **学习能力**：本科基础够用，LLM 方向自学 + 实习也能跟上
3. **机会成本**：再读 3 年 vs 早工作 3 年，后者对我更有价值
4. **行业窗口**：AI 行业在快速发展，等 3 年变化可能很大

**如果打算读研**：
- 简单说明未来的研究方向即可
- 不要贬低本科就业路径

## 二、实习类（校招重点）

### Q：你在实习中做了什么？

**STAR 法则**：
- **S**：业务背景（公司在做什么）
- **T**：你的具体目标
- **A**：你做了哪些关键事情
- **R**：结果（量化）

**模板**：
> 我在 <某某 AI Agent 初创公司> 实习，主要做 LLM 应用工程。实习期间我：
> 1. 独立负责 Agent 工具调用层的设计与实现，让 Agent 能调用 10+ 工具
> 2. 优化 RAG 检索流水线，召回率从 X% 提升到 Y%
> 3. 引入 LangSmith 追踪，方便团队排查问题
> 4. 编写团队 LLM 应用开发规范文档

**关键**：
- **量化结果**（哪怕不是 10w+，0.1% 也比"提升"两个字好）
- **主动做了什么**（不是"参与了 XX"，而是"独立负责 XX"）

### Q：实习中遇到的最大挑战？

**准备 2-3 个故事**：
- 技术难点（如 RAG 召回率低怎么排查）
- 协作难点（如和 PM / 算法工程师 / 后端的协作）
- 学习难点（如 2 周内从零上手 LangGraph）

### Q：实习导师 / Leader 怎么评价你？

**真实回答 + 适度包装**：
- 不要编得太离谱
- 最好有一个具体的反馈（如"代码 review 时 Leader 说我考虑边界情况很细致"）
- 如果没有，反过来问："Leader 还没给我正式评价，但我自己感觉..."

## 三、项目类

### Q：你做过最复杂的项目是什么？

**校招答题思路**：
- 不要选「最有影响力的」，要选**「最体现你能力的」**
- 项目不一定要大，但要能讲清楚「你做了什么」「为什么这么做」
- 最好有量化结果（性能 / 用户量 / 准确性）

**模板**（以 AI-Me 为例）：
> AI-Me 是我独立做的 AI 数字分身项目，规模不大但麻雀五脏俱全：
> - 5 类意图路由、3 路混合检索、⟪n⟫ 引用标注
> - LangSmith 追踪 + RAGAS 评估
> - 我负责全部后端 + 前端，约 2000 行代码
>
> 最难的是 ⟪n⟫ 引用标注机制——让 LLM 真的按编号标注，不能幻觉。我做了 prompt 调优 + 后处理正则两层兜底。

### Q：项目中最难的技术点是什么？

**避免泛泛而谈**：
- 不要说"系统设计很难"（太抽象）
- 聚焦一个点深挖：
  - 是什么问题？
  - 你尝试了哪几种方案？
  - 为什么最终选了这个方案？
  - 落地效果如何？

### Q：你项目里某个具体模块是怎么实现的？

**提前准备 3-5 个技术深挖点**：
- LangGraph 的节点编排
- Milvus 的 schema 设计
- Rerank 的调用时机
- 流式 SSE 的实现
- 限流的设计

## 五、软技能类

### Q：你的优势？

**校招生 5 3 个核心**：
1. **基础扎实**：GPA + 竞赛 + 课程
2. **学习速度快**：实习中 2 周上手新技术
3. **工程能力完整**：从需求到部署全流程
5. **年轻可塑**：校招生，学习意愿强

### Q：你的劣势？

**诚实 + 已意识到 + 在改进**：
1. **工程经验不足**：少 2-3 年实战（已规划：跟着 senior 学习）
2. **算法深度不够**：Transformer 原理懂，没改过框架源码（已规划：读 vLLM 源码）
3. **业务理解浅**：模块级工作，没有完整业务闭环（已规划：主动问 PM）

### Q：你抗压能力怎么样？

**讲一个具体故事**：
- 实习中 deadline 紧的时候怎么扛过来
- 主动加班 / 周末学习的经历
- 应对突发 bug 的经验

## ⚠️ 校招面试注意事项

1. **不要背稿**：AI 的回答是参考，真实面试要自然流畅
2. **诚实**：不知道的就说不知道，比瞎编好得多
3. **量化**：尽量用数字（性能提升 X% / 处理 Y 万数据）
4. **STAR 法则**：所有项目 / 实习经历都用 STAR 组织
5. **基础 > 项目**：校招更看重基础（算法 / OS / 网络），项目只是加分项
6. **潜力 > 经验**：展示学习速度和成长空间
7. **不要贬低对手**：不要 diss 学校 / 课程 / 前 Leader
8. **反向提问**：一定要问！问得好比答得好更能加分

## 🎯 校招 vs 社招的核心区别

| 维度 | 校招 | 社招 |
| --- | --- | --- |
| **考察重点** | 基础 + 潜力 + 学习能力 | 项目深度 + 业务理解 + 落地能力 |
| **期望水平** | 能干活就行 | 能独立负责模块 |
| **薪资** | 按市场价，不看经验 | 看经验 / 项目深度 |
| **项目经验** | 不要求有，但有加分 | 必须有，且要深 |
| **表达期望** | 谦虚 + 好学 | 自信 + 主导 |
| **劣势回答** | 短板 + 在改进 | 不存在明显短板 |

---

> 💡 **关键提示**：校招面试官对应届生的容错率比社招高，更看重「是否能培养」，而不是「现在能做什么」。所以展示你的**学习速度 + 基础扎实 + 主动思考**比包装项目更重要。
